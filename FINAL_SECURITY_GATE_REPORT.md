# Финальный security gate — Xneon Launcher 1.0.8-pre1

**Security verdict: gate не пройден. Решение о выпуске: NOT READY.**

Локальная проверка не заменяет валидацию полного жизненного цикла Windows и проверки доверия к обновлению. Контекст предыдущих раундов сохранён в SECURITY_AUDIT_REPORT.md, SECURITY_REMEDIATION_REPORT.md, SECURITY_THREAT_MODEL.md, SECURITY_REGRESSION_TESTS.md, SECURITY_REMAINING_RISKS.md, BUN_NATIVE_API_AUDIT.md, FINAL_PRODUCTION_READINESS_REPORT.md и BUN_MIGRATION_REPORT.md.

## Конфигурация

По манифесту, lockfile и конфигурации проверены Bun 1.4.4, Electrobun 2.0.6, Hutch 0.29.0, React 19.2.8, Vite 8.3.5, TypeScript 7.0.2 и восемь XNLC workspace-пакетов. Продукт Xneon Launcher использует ID com.xneonlauncher.app, профиль Windows по умолчанию %APPDATA%\xneonlauncher и data.db внутри него. Каналы разделяют каталоги установки и артефакты. Профиль по умолчанию общий. Изоляция данных между установленными экземплярами требует отдельного решения о продуктовой политике и проверки в VM.

## Обзор исходников

| Область | Установлено | Открыто |
| --- | --- | --- |
| Agent и MCP | runtime.ts связывает одноразовое подтверждение с ID действия, проверяет отказ и остановку перед вызовом. Вывод модели, файлов и MCP следует считать недоверенными данными. | FSG-01. Согласие хранится в renderer. Привилегированные MCP-вызовы в preload и main не требуют отдельного подтверждения main. Угроза требует доступа к привилегированному WebView. Нужна граница авторизации вне renderer с привязкой операции, аргументов и окна. |
| Секреты | cloud/token-store.ts использует DPAPI CurrentUser, миграцию при чтении и compare-and-swap при refresh. AI status RPC возвращает hasApiKey, общий settings RPC блокирует параметры AI. Ошибки AI используют фиксированные сообщения, авторизованный fetch останавливает redirect. | Старые копии SQLite/WAL, отказ DPAPI, успешные ответы провайдера, диагностические пути облачных провайдеров и реальное восстановление профиля требуют проверки. |
| IPC и WebView | Launcher view ограничивает navigationRules и разрешения схем. Общие RPC имеют разные уровни проверки аргументов. В актуальном коде лаунчера обработчик xneon: не найден. | Не доказана авторизация всей матрицы RPC, включая файловые и MCP-операции. Настоящий WebView2 не проверен. |
| Minecraft import | Modrinth и ряд ZIP/CurseForge путей используют resolveSafeIntentFilePath. Помощник проверяет относительный путь, корень и существующие ссылки. Для просмотра Modrinth-пака проверяется SHA-512 при наличии хеша. | Полное покрытие FTB и иных импортов, коллизий Windows, гонок файловой системы, пределов распаковки и всех переходов manifest → загрузка не доказано. |
| Network | Для отдельных CDN-загрузчиков есть HTTPS, allowlist, ограничение числа redirect и проверки каждого перехода. S3 и WebDAV принимают пользовательские endpoints. | Полное покрытие SSRF, private IP, DNS rebinding и лимитов ответа не установлено. Политика должна сохранять осознанную поддержку локальных серверов S3/WebDAV. |
| Updater | SDK проверяет схему, канал, идентификатор, платформу, архитектуру, имя пакета, ограничения JSON и поля размера/SHA-256 для v2. Main перед handoff останавливает операции, MCP, relay и SQLite. | FSG-02. Feed использует HTTPS GitHub Releases, отдельная подпись манифеста с доверенным ключом приложения не обнаружена. SHA-256 из того же feed подтверждает целостность пакета. FSG-03. SDK определяет наличие обновления по отличию hash, запрет downgrade по порядку версий не найден. Legacy fallback при 404 v2 ослабляет обязательность digest. Подлинность, downgrade, атомарная замена, восстановление после сбоев и rollback блокируют выпуск. |

Динамическое воспроизведение атак не выполнялось. Выводы FSG-01–03 основаны на доступных точках вызова и условиях в исходниках, без заявления о продемонстрированной эксплуатации. Обзор охватил приоритетные маршруты. Полное покрытие всех обработчиков и импортов не подтверждено.

## CI и исправление

FSG-04. Workflow выдавал contents: write всем задачам, включая загрузку toolchain и сборку. В .github/workflows/release.yml по умолчанию установлен contents: read, запись оставлена задаче release. Checkout больше не сохраняет учётные данные в обеих задачах. YAML и инварианты прав проверены локально, код 0. GitHub Actions не запускался.

Release запускается на push тега v*, PR-триггера нет. Build использует Windows runner, Bun 1.4.4, Hutch 0.29.0 и frozen lockfile. Явное задание архитектуры runner и проверка содержимого артефактов перед публикацией в workflow отсутствуют. Текущий workflow публикует Stable. Canary не проверяется этим workflow. Установщик Hutch скачивается и выполняется во время сборки, версия фиксирована, отдельный digest скрипта не закреплён. OAuth client secrets, переданные генератору сборки, попадают в настольный пакет по конструкции. Для production нужно отделять публичные идентификаторы от секретов, которым требуется конфиденциальность.

# XNLC/Share

Самостоятельный сервис общих сборок. Требуются Node.js 24 и pnpm 11+. Метаданные находятся в SQLite, внешние объекты — в отдельном каталоге по SHA-256. JAR из подтверждённого каталога хранится в manifest как ссылка на точную версию.

## Локальный запуск

Из корня репозитория:

```powershell
pnpm install
Copy-Item services/share/.env.example services/share/.env
pnpm run share:server
```

В другом терминале:

```powershell
$env:XNLC_SHARE_URL = "http://127.0.0.1:8787"
pnpm run dev
```

Адрес рабочего сервиса по умолчанию: `https://xnlc-share.stepangavrilov736.workers.dev`. `XNLC_SHARE_URL` переопределяет адрес для разработки. Пользователю не требуется вводить URL, bearer token или ID репозитория.

Для одновременного запуска локального сервиса и dev-лаунчера можно использовать одну команду `pnpm run dev:share`.

Для Share достаточно хотя бы одного сохранённого аккаунта любого типа, кроме `offline`. Активным при этом может оставаться offline-аккаунт. Отдельной регистрации, формы входа и пароля Share нет. Токены игровых аккаунтов сервису не передаются.

Откройте сборку → «Совместный доступ» → «Поделиться». Подключение выполняется автоматически.

## Пользовательский сценарий

1. Опубликуйте сборку. Моды, ресурспаки и шейдеры определяются автоматически. На вкладке «Файлы» явно выберите дополнительные файлы: изначально ничего не выбрано.
2. Сервер получает manifest и необходимые внешние объекты. Создаются Initial Commit и `main`.
3. Выберите права по ссылке — редактор или читатель — и отправьте ссылку другу. Ссылка рассчитана на одного пользователя и действует семь дней. Создатель меняет роли и удаляет участников в управлении сборкой; редактор публикует изменения, читатель получает обновления. Прежние роли contributor и maintainer автоматически переводятся в editor при запуске сервера.
4. Получатель видит владельца, версию Minecraft, загрузчик, содержимое и источники до принятия приглашения. Подтверждение создаёт отдельный инстанс без перезаписи существующих сборок.
5. После применения содержимое пересканируется штатным `scanIntentDir`; списки модов, ресурспаков, шейдеров и привязка фиксируются транзакцией. Событие обновляет кэш списка сборок. Minecraft и загрузчик устанавливаются существующим механизмом обычного запуска.
   Настройки запуска сборки также входят в снимок: флаги переопределения, память, JVM-аргументы, выбор Java, размер окна и выбранный аккаунт. Java сопоставляется с локальными установленными версиями, аккаунт — с уже добавленными записями по типу и UUID/имени; токены, пароли и локальные ID аккаунтов не передаются. При отсутствии совпадения используется локальный выбор по умолчанию. Изменения настроек видны в истории, участвуют в обновлениях, конфликтах и откате. Старые публикации без этих полей поддерживаются.
6. При открытии сборки и перед запуском проверяется последняя версия. Обновление требует предпросмотра, а конфликтующие локальные изменения — явного выбора.
7. В «Истории и версиях» доступны история и ветки. Для отката выберите старую запись, нажмите «Вернуться к этой версии», проверьте изменения и подтвердите. Ветка и локальные файлы вернутся к выбранному состоянию, прежняя история сохранится. Теги, релизы, PR и stash не отображаются; создание новых релизов отключено.
8. Создатель может удалить публикацию в управлении совместным доступом. Сервер удаляет её историю, участников, приглашения и внешние объекты, которые не нужны другим публикациям. Локальные сборки остаются у всех; при следующей проверке лаунчер снимает привязку к удалённой публикации. На сервере остаётся только отметка об удалённом ID для такого отключения.

Ссылки `xneon://share/invite/…` принимаются лаунчером. Ассоциация протокола устанавливается для упакованного приложения; dev-сборка не перезаписывает системную ассоциацию. В dev можно вставить ссылку в окно приглашений.

## Конфигурация

| Переменная | Где | Назначение |
| --- | --- | --- |
| `XNLC_SHARE_URL` | Лаунчер | Базовый URL сервиса; HTTPS, либо HTTP только для loopback |
| `CURSEFORGE_API_KEY` | Лаунчер main | Официальный ключ CurseForge для разрешения локальных ссылок |
| `SHARE_HOST` | Сервис | Интерфейс прослушивания, по умолчанию `127.0.0.1` |
| `SHARE_PORT` | Сервис | Порт, по умолчанию `8787` |
| `SHARE_DATA_DIR` | Сервис | SQLite и каталог объектов, по умолчанию `.share-data` |
| `SHARE_BOOTSTRAP` | Сервис | Необязательные заранее выданные тестовые сессии; обычный вход их не требует |

Служебная сессия создаётся автоматически: установка лаунчера подписывает одноразовый challenge ключом Ed25519. Закрытый ключ и сессия сохраняются через Electron safeStorage. В серверной БД хранятся хеши токенов. Истечение сессии не требует действий пользователя. Наличие не-offline аккаунта проверяется в main перед каждым обращением к сервису; тип, UUID и игровые токены из renderer для этой проверки не принимаются.

Идентификатор совместной работы принадлежит установке лаунчера: переключение активного игрового аккаунта не лишает доступа к своим сборкам. Ник используется как отображаемое имя. Это не серверная проверка подлинности игрового аккаунта. Старая сессия первого прототипа при наличии автоматически обменивается с переносом прав на опубликованные репозитории; история коммитов сохраняется.

Схема локальной БД лаунчера поднята до версии 10. Таблица `shared_instances` хранит репозиторий, ветку, применённый и последний коммиты, аккаунт, роль, состояние и время обновления. Старые экспериментальные JSON-привязки в settings автоматически не присваиваются другому аккаунту.

## HTTP

Основные действующие маршруты:

- `POST /v1/auth/challenge`, `POST /v1/auth/launcher`, `GET /v1/auth/me`: автоматическое подключение лаунчера. Маршрутов регистрации и входа по паролю нет.
- `POST /v1/repositories`, `GET /v1/repositories/{id}`, `GET /v1/repositories/{id}/commits`.
- `POST /v1/repositories/{id}/commands`: коммиты, ветки, участники; проверка прав и ожидаемого HEAD. Старые операции stash и PR сохраняются для совместимости; создание релизов не поддерживается.
- `POST /v1/repositories/{id}/invites`, `GET /v1/invites/{token}`, `POST /v1/invites/{token}/accept`.
- `GET /v1/invitations`, `GET /v1/invitations/{id}`, `POST /v1/invitations/{id}/accept`: персональные входящие приглашения.
- `/v1/repositories/{id}/objects/{hash}`: отдельная двоичная передача; перед PUT запрашивается одноразовый ticket.

## Проверки

```powershell
pnpm run share:test
pnpm run share:test:electron
pnpm run share:test:live
pnpm run build
```

Последняя команда live обращается к настоящему Modrinth API и проверяет точную идентификацию скачанного Sodium. Обычные тесты независимы от внешнего каталога. Нагрузочный сценарий 300 файлов использует синтетический каталог и настоящий HTTP-сервис; это проверка механизма, а не замер реальной большой сборки.

## Развёртывание и текущие ограничения

Сервис запускается отдельным Node-процессом с постоянным томом `SHARE_DATA_DIR`. Для доступа из интернета требуется HTTPS reverse proxy. Не размещайте SQLite и objects в публичном web-root; резервируйте их согласованно.

Cloudflare Worker использует общую логику `service.mjs`: постоянная SQLite в Durable Object хранит метаданные и транзакции, приватный R2 bucket — содержимое файлов. Обработчик Node остаётся в `server.mjs`. Внешний файл ограничен 32 MiB; содержимое проверяется и буферизуется в памяти. Подробности развёртывания — в [WORKERS.md](WORKERS.md).

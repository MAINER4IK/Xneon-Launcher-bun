# Модель угроз Xneon Launcher

## Область и допущения

Локальный Windows-лаунчер с привилегированным процессом main и WebView. Пользователь может импортировать файлы, выбирать внешние сервисы и запускать сторонний Java-код. Внешний источник может контролировать содержимое ответа, файла или текста, переданного модели. Чтение профиля на диске или выполнение кода в renderer рассматриваются как отдельные предпосылки.

## Компоненты, границы и активы

| Граница | Активы и входы | Наблюдаемые контроли и пробелы |
| --- | --- | --- |
| WebView → main (`electrobun/platform/desktop.ts`, `electrobun/preload.ts`) | RPC к локальным файлам, SQLite, настройкам, сетевым операциям и процессам | Навигация окна лаунчера ограничена. Авторизация отдельных RPC требует инвентаризации. |
| Модель → runtime → MCP (`packages/xnlc-agent/src/runtime.ts`, `electrobun/main/agent-mcp.ts`) | Запросы инструментов, вывод MCP, разрешения, переменные окружения | Проверяются аргументы доменных инструментов и разрешения режима. Подтверждение привязано к действию в renderer. Main принимает запросы MCP через мост. Stdio наследует возможности локального процесса. |
| Облачные сервисы и OAuth → main (`electrobun/main/auth.ts`, `electrobun/main/cloud/token-store.ts`) | Callback, аккаунты, ключи и резервные копии | В просмотренном callback сверяются origin, путь и ожидаемый state. Облачные токены сохраняются в SQLite как JSON. |
| Архив и CDN → установка (`electrobun/main/builds/helpers.ts`, `electrobun/main/cloud/handlers.ts`, `packages/xnlc-core/src/core/java-manager.ts`) | Конфигурации, моды, Java, каталог инстанса, работоспособность хоста | Помощник импорта проверяет вложенность и существующие ссылки. Облачный импорт и Java используют отдельные пути извлечения. |
| Feed обновления → SDK и нативный helper (`electrobun/main/updater.ts`, `scripts/test-native-update.ts`) | Целостность артефактов, идентичность канала, доступность приложения | Перед передачей управления останавливаются сервисы и закрывается БД. Проверку digest и подготовку охватывает отдельный тест. |
| Main → SQLite (`electrobun/db/core.ts`) | Аккаунты, чаты, WAL, миграции | Базовые методы привязывают значения параметрами. Полная инвентаризация динамического SQL и копий профиля открыта. |

## Приоритеты

- **Высокий** — целостность обновлений и импортов. Внешние данные пересекают границы записи на диск и установки кода. Нужна проверка лимитов, ссылок и состояния после нативной передачи управления.
- **Высокий** — привилегии MCP. Компрометация процесса stdio или renderer влияет на профиль и секреты. Проверять подтверждение в main и жизненный цикл транспорта.
- **Средний** — доступ к секретам. Копии SQLite и renderer увеличивают область раскрытия. Изолировать секреты в main и хранилище ОС.
- **Средний** — недоверенный контент в контексте модели. Логи, вложения, описания модов и MCP-ответы могут побудить модель запросить действие. Решение принимает прикладная проверка режима и полномочий.

Тесты и инструменты сборки отделены от среды пользователя. Уведомления зависимостей разработки не повышают оценку рабочего пути без данных о его достижимости.

## Изменения границ во втором раунде

- WebView получает статус наличия AI-ключа. Ввод нового ключа проходит renderer и специализированный RPC, после успешной записи форма очищает его. Только main извлекает ключ для выполнения запросов. Сохранённый ключ связан с endpoint и протоколом.
- Ошибки внешнего AI-провайдера пересекают IPC как фиксированное сообщение категории. Заголовки и полные HTTP-ответы остаются за границей main. Авторизованные HTTP-запросы AI останавливаются при redirect.
- Cloud SQLite хранит новые и мигрированные записи в DPAPI. Доступ к копии базы отдельно от учётной записи Windows больше не даёт непосредственного чтения мигрированных значений. Процессы под той же учётной записью и прежние копии остаются в модели угроз.
- Refresh сохраняет результат только пока запись соответствует исходному снимку. Это отделяет долговременную запись от уже начавшегося сетевого запроса и предотвращает восстановление удалённых или заменённых токенов через поздний refresh.

# Workflow экспериментального выпуска

Цель — MAINER4IK/Xneon-Launcher-bun, main, тег v1.0.8-pre1. Исходный checkpoint e6b67718017f66bbb97ba3db61f2a784f9cb384c.

Workflow ограничен личным репозиторием. Ручной запуск проверяет кандидата без публикации. Push точного тега запускает сборку, отдельную валидацию и публикацию после успешной проверки. Сборка и валидация имеют contents: read, публикация — contents: write. Checkout не сохраняет учётные данные. Build не получает OAuth и registry secrets. Windows runner проверяет X64. Bun 1.4.4, Hutch 0.29.0 и frozen lockfile закреплены.

Bootstrap Hutch загружается по HTTPS, проверяется по SHA-256 и только потом запускается. Дайджест 185cc615d3d1b6e7156c104beb902cce3f4b9f35cb3d14df047586aa432883e7 относится к просмотренному bootstrap с официального хоста. Изменение скрипта останавливает сборку. Это закрепление проверенных байтов, отдельной подписи поставщика не обнаружено. Bootstrap проверяет размер и SHA-256 архива Hutch по manifest той же инфраструктуры. Независимое подтверждение подписи и происхождения всего toolchain остаётся открытым. TLS не отключался. [Официальный репозиторий Hutch](https://github.com/blackboardsh/hutch)

Публикация ограничена автономным Windows x64 установщиком и SHA256SUMS.txt. Манифесты и архив обновления служат входами валидации и не передаются в релизные вложения.

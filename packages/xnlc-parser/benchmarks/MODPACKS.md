# Сравнение на сборках Modrinth

Снимок формируется из поиска Modrinth `project_type:modpack`, `index=downloads`. Для каждого проекта выбирается последняя доступная версия типа release с `.mrpack` (при отсутствии release — другая доступная версия). Манифест содержит место в поисковой выдаче, версию сборки, ссылки, SHA-1 и список модов; ошибки и пропущенные проекты фиксируются. Серверные файлы с `client: unsupported` исключаются. Моды из `overrides` и `client-overrides` добавляются, при совпадении пути клиентский override имеет приоритет. Дубликаты сохраняются в составе отдельных сборок, но на диске хранятся один раз по SHA-1.

```powershell
bun packages/xnlc-parser/benchmarks/modpacks-50.ts <каталог> index
bun packages/xnlc-parser/benchmarks/modpacks-50.ts <каталог> download
bun packages/xnlc-parser/benchmarks/setup-xmcl.ts <изолированный-каталог-xmcl>
$env:XNLC_BENCH_PACK_SCAN='1'
bun packages/xnlc-parser/benchmarks/xmcl-scan.ts xnlc <каталог> <изолированный-каталог-xmcl> xnlc.json
bun packages/xnlc-parser/benchmarks/xmcl-scan.ts xmcl <каталог> <изолированный-каталог-xmcl> xmcl.json
bun packages/xnlc-parser/benchmarks/xmcl-compare.ts xnlc.json xmcl.json compare.json
```

`download` проверяет SHA-1 и отдельно фиксирует расхождения размера с индексом: среди реальных сборок встречаются неверные размеры при совпадающем SHA-1. Загрузку можно повторить для пропущенных файлов. Число ошибок и файлов без корректного SHA-1 необходимо учитывать при интерпретации результатов. `setup-xmcl.ts` проверяет registry SHA-512 для опубликованных архивов XMCL 3.4.3 и его зафиксированных компонентов, исправляя только `main` в повреждённых опубликованных manifests. Их код остаётся неизменным. npm-lock фиксирует остальные зависимости.

Оба режима используют Bun в отдельных процессах и открывают файлы с диска. XMCL использует отдельные публичные функции чтения Fabric, Quilt, Forge/NeoForge TOML, legacy JSON и LiteLoader с одним открытым filesystem. XNLC вызывает `analyze`: он дополнительно обнаруживает вложенные JAR и другие форматы. Это **сравнение metadata**, а не полного `readForgeMod` XMCL: ASM-сканирование классов XMCL здесь отключено, как и необязательное сканирование классов XNLC. Сверяются ID, версия и загрузчик, а для Fabric/Quilt дополнительно SHA-256 канонического JSON со всеми полями и зависимостями. Семантика разрешения зависимостей не сравнивается.

`XNLC_BENCH_PACK_SCAN=1` повторно сканирует каждый файл в каждой сборке, сохраняя время и ошибки по сборке; иначе каждый уникальный файл сканируется один раз. Дополнительно `XNLC_BENCH_HASHES=1` для обоих режимов включает общий код потокового SHA-1 и CurseForge fingerprint XNLC: это оценка стоимости хеширования в одном сценарии, а не сравнение разных реализаций хеширования. Результат содержит длительность и peak RSS всего процесса; его нужно повторить в нескольких отдельных процессах, чередуя порядок, и отдельно указать состояние кэша ОС и постороннюю нагрузку. Диск и API недоступных файлов нельзя считать успешными результатами. Наличие одинаковых ID и версий также не доказывает одинаковую полноту и корректность разбора.

Для повторных проходов используется `xmcl-repeat.ts <каталог> <каталог-xmcl> <каталог-результатов> 3`. Необязательный `XMCL_NODE_EXECUTABLE` задаёт Node.js для процесса XMCL, если поддерживается запуск TypeScript; это отдельный сценарий сравнения сред и его нельзя сочетать с `XNLC_BENCH_HASHES=1`.

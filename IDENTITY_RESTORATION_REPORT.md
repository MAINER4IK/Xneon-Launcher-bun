## Технические имена и границы миграции

- `bin/launcher.exe`, `bin/bun.exe`, внутренний `Xneon Launcher-Setup.exe` в ZIP, названия архивов и служебные файлы Electrobun являются частью формата пакета. Имя прежнего установленного приложения, `Xneon Launcher.exe`, подтверждено локальным `release/win-unpacked`. Изменение имени внутреннего launcher затронуло бы штатный запуск и перезапуск.
- `XNEON_BUN_DATA_DIR` остаётся явным техническим переопределением для тестов. Префикс мьютекса `XneonLauncherBun-` сохранён, чтобы старые тестовые и восстановленные пакеты использовали один механизм блокировки профиля. Суффикс резервной копии `.electrobun-v…-to-v…` обозначает способ её создания.
- Прежний манифест регистрировал протокол `xneon:` под именем XNLC Share. Встроенная регистрация схем Electrobun 2.0.6 ограничена macOS. В Windows текущий поток Share принимает код приглашения. Восстановление системного deep link требует отдельной регистрации и обработки входящих ссылок. Исторических файловых ассоциаций в исходном манифесте нет. Внутренние `avatar:` и `xnl-theme:` служат маршрутам ресурсов.
- Electrobun сверяет ID манифеста с ID установленного пакета. Установки с тестовым ID требуют перехода через новый установщик после удаления прежней установки с сохранением профиля. Обёртка читает сведения о прежней установке и показывает сообщение. Удаление она не выполняет.
- Windows — проверяемая платформа. Для macOS и Linux общий идентификатор задан в конфигурации. Пакеты, отображение ярлыков, интеграция с рабочим столом и использование прежнего значка на этих платформах требуют проверки.

## Проверка

- `pnpm run build` собрал TypeScript, интерфейс, Bun-воркеры, пакет Stable и однофайловый установщик. `pnpm run test:desktop` под Bun 1.4.4 — 63 из 63.
- Проверены PE-поля внешнего установщика, нативные метаданные установщика и манифесты обновлений Stable и Canary. В обоих каналах ID — `com.xneonlauncher.app`, а в метаданных приложения и установщика отображается Xneon Launcher. Локальный Canary хранится отдельно в `.tmp/identity-canary-artifacts`.
- Распакованный Stable запущен из тестового каталога с той же структурой, что у управляемой установки. Подтверждены заголовок окна Xneon Launcher, совпадение SHA-256 `Resources/app.ico` с `build/icon.ico` и значение AppUserModelID в метаданных. Тестовый `%APPDATA%\xneonlauncher\data.db`, созданный через `better-sqlite3`, открыт и обновлён с версии 11 до 12. Контрольная запись сохранилась в рабочей БД и резервной копии. Каталог тестового профиля с суффиксом `-bun` не появился.
- Из собранного EXE отдельно проверено распознавание существующего NSIS-деинсталлятора с путём в кавычках и отказ для отсутствующего файла. Проверка использовала файлы внутри рабочего каталога.
- Установщик и деинсталлятор через GUI не запускались. Такая проверка записала бы системные ярлыки и реестр за пределами разрешённого каталога. Соответственно, фактическая запись Windows Apps & Features, издатель этой записи, группировка закреплённого ярлыка и отсутствие дублей в реальной системе требуют отдельной проверки.
- Сетевой переход между версиями не проверялся. Hutch сообщил `HttpConnectionClosing` при загрузке прежних метаданных и собрал полные пакеты без delta. Публикации и релизы не создавались.

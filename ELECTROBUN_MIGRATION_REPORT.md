# Миграция Xneon Launcher на Electrobun

Дата проверки — 10 ноября 2026 г. Целевая платформа — Windows x64. Имя приложения и установщика — Xneon Launcher. В Windows-бандл включена иконка из build/icon.ico.

Исходный аудит прочитан из `C:\xnlauncher\ELECTROBUN_MIGRATION_AUDIT.md`. Для реализации использована уже существовавшая отдельная копия в `C:\xnlauncherbun`, включая её локальные изменения. Оригинал использован только для чтения. Хеш вывода `git status --porcelain=v1 -uno` оригинала до и после миграции совпал.

## Сборка и запуск

Требования к сборке — Node.js для Vite и pnpm, pnpm 11, Bun 1.4.4 и Hutch 0.29.0. Electrobun закреплён на 2.0.6. В собранном приложении Bun входит в комплект, а интерфейс использует системный WebView2.

В `C:\xnlauncherbun`:

```powershell
pnpm install --frozen-lockfile
pnpm run dev
pnpm run build
```

`pnpm run build:dev` только собирает dev-бандл. `pnpm run dev` запускает этот бандл с собранным Vite-интерфейсом. `pnpm run build` собирает и проверяет workspace-пакеты, проверяет TypeScript в UI и backend, собирает Vite и воркеры, затем формирует stable-артефакты через Hutch.

- Dev-бандл находится в `build-electrobun\dev-win-x64\XneonLauncher-dev`.
- Однофайловый установщик Windows x64 находится в `release-electrobun\Xneon Launcher-Setup.exe`. Он сам распаковывает встроенный пакет Hutch во временную папку. ZIP остаётся промежуточным артефактом сборки.
- Для запуска stable-бандла без установки распакуйте вложенный архив из `build-electrobun\stable-win-x64\XneonLauncher\Resources` внутри целевого проекта и запустите `XneonLauncher\bin\launcher.exe` из распакованной папки. Верификация выполнена этим способом.

На машине проверки загрузка точной версии Bun через Hutch завершалась `HttpConnectionClosing`. Для проверок использована локальная копия кэша Hutch внутри `.hutch\toolchain-home` и Windows x64 бинарник из официального npm-пакета Bun 1.4.4, сверенный по SHA-512. Команды сборки в этой копии можно повторить с указанным кэшем:

```powershell
$env:HUTCH_HOME = 'C:\xnlauncherbun\.hutch\toolchain-home'
$env:XNEON_HUTCH_EXECUTABLE = (Get-ChildItem "$env:HUTCH_HOME/releases/hutch/0.29.0" -Recurse -Filter hutch-engine.exe | Select-Object -First 1).FullName
$env:Path = "$env:HUTCH_HOME\toolchains\bun\1.4.4\windows-x64;$env:Path"
pnpm run build
```

## Перенос

- React 19, Vite 8, Tailwind CSS 4, TypeScript и восемь локальных workspace-пакетов XNLC сохранены. Каталоги `electrobun/main` и `electrobun/db` сохраняют структуру исходных модулей. Desktop entrypoint запускается Bun, а импорты Electron заменены локальными платформенными адаптерами.
- Запросы и события проходят через Electrobun RPC. Схема опирается на `IpcInvokeMap` и `IpcEventMap`. Реестр повторно использует существующие обработчики. UI использует `window.electrobunAPI`, а начальная тема поступает в доверенный документ через preload.
- Профиль Windows по умолчанию использует `%APPDATA%\xneonlauncher-bun`. `XNEON_BUN_DATA_DIR` задаёт отдельный корень данных для проверки. Переиспользованы существующая схема SQLite и логика миграций. Соединения приложения используют `bun:sqlite`. `better-sqlite3` остаётся dev-зависимостью отдельного Node.js сервиса Share и его тестов.
- Windows-адаптеры обеспечивают диалог сохранения, шифрование DPAPI и блокировку второго процесса на профиль. Внешние окна OAuth открываются в изолированном WebView без привилегированного RPC. Локальные аватары и медиа тем обслуживаются только через loopback с уникальным токеном сессии. Для обычных файлов из HTML input и drag-and-drop используются временные копии с ограничением размера.
- Сканирование JAR, создание архивов и запуск Minecraft используют отдельные Bun-воркеры, которые входят в бандл. Скопированный исходный `node_modules` перемещён в резервный каталог `.migration-node-modules`. Активный граф зависимостей установлен заново в целевом проекте.

## Ограничения и оставшиеся проверки

- Полная функциональная эквивалентность исходной версии остаётся открытой. Нужны сквозные прогоны входа OAuth с реальными аккаунтами, запуска Java/Minecraft, XN-Connect, Discord RPC, MCP stdio, файлового импорта и диалогов экспорта.
- Приглашения Share принимаются по коду в окне установки общей сборки. Блокировка второго экземпляра проверена на Windows.
- Новости открываются системным браузером. Для обработки изображений используется PNG. При импорте из HTML поддерживаются обычные файлы до 64 МиБ на файл и 256 МиБ за сессию. Перетаскивание папок, файловые форматы системного буфера и чтение GPU требуют отдельных адаптеров.
- Windows-установщик собран без подписи Authenticode. Запуск проверен на распакованном бандле. Стабильные обновления настроены на GitHub Releases репозитория XneonTeam/Xneon-Launcher. Для активации опубликуйте манифесты и архив обновления из release-electrobun в стабильном релизе с отметкой Latest. Стабильный канал и beta-выбор в UI пока не переключают источник обновлений. Поддержка macOS и Linux в этой проверке не подтверждена.


## Повторная проверка Windows x64

- Сверены 283 уникальные литеральные регистрации запросов в исходном Electron и целевом backend. Имена совпадают. Сравнение имён покрывает только литеральные регистрации и не доказывает эквивалентность поведения обработчиков.
- TypeScript и 67 тестов Share и агента прошли. Эти тесты не покрывают нативные диалоги, запуск Java или реальные OAuth-сессии.
- Журнал production-лаунчера подтвердил запуск Java воркером и завершение с кодом 0. Проверка выявила обращение запуска по умолчанию к каталогу Minecraft старого профиля. Выбор каталога изменён на корень Minecraft активного профиля Electrobun. Явный путь сборки по-прежнему имеет приоритет.
- GitHub workflow использует Windows runner и Hutch. Автоматическая публикация релиза этим workflow ещё не проверена. Desktop-тесты перенесены в `tests/electrobun` и запускаются через `pnpm run test:desktop`.
- Нативный clipboard-адаптер выдаёт только изображение PNG. Файловый буфер, перетаскивание папок и чтение GPU имеют неполное покрытие. Beta-канал сохраняет настройку без переключения источника. Поведение OAuth, нативных диалогов, Discord RPC, XN-Connect и обновления с GitHub ещё нужно проверять сквозными сценариями.
- Рабочий профиль Windows перенесён из проверенного основного файла SQLite. При подключении старого WAL копия базы не проходила проверку целостности. Последние записи, сохранившиеся только в WAL, могли отсутствовать.

## Сквозные проверки после переименования

- 61 desktop-тест прошёл на Bun, включая пересылку TCP и состояние running после ответа тестового relay XN-Connect.
- Нативные Windows-диалоги в отдельном production-бандле успешно вернули путь выбранного файла и путь сохранения.
- Microsoft, Ely.by и XNSkins выдали коды устройства через реальные endpoints. Тестовый OAuth-редирект прошёл через sandbox WebView2 и loopback callback с проверкой state. Завершение входа с реальными аккаунтами и обмен кода на токен требуют ручного входа.
- Реальный Discord Desktop ответил READY на RPC IPC. Внешнее отображение Rich Presence не проверено.
- Реальный XN-Connect API принял сохранённую сессию и вернул список узлов и туннелей. Пересылка TCP проверена с локальным relay. Публичное подключение игрока ещё не проверено.
